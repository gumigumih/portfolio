# Portfolio design guidelines

このポートフォリオは、採用・案件獲得向けのケーススタディ資料として、落ち着いた情報設計を優先する。

## Shadow

影は「階層」や「重なり」を表す場合だけ使う。

- 通常のセクション、情報カード、スキルカード、TOCには影を使わない
- 静的なカードは `border border-slate-200 bg-white` を基本にする
- クリックできるプロジェクトカードは、通常時は影なし、hover時のみ `hover:shadow-sm` までにする
- モーダル、オーバーレイ、ヒーローの画像重なり表現では影を使ってよい
- ボタンは影で押せる感を出さず、色・罫線・hoverの背景色で状態を表す

## Interaction

- クリックできる要素は `cursor-pointer` を明示する
- モーダル内などクリック対象ではない面は `cursor-default` に戻す
- hover表現は、背景色・罫線色・軽い移動・必要最小限の影で示す

## Surface

- 罫線は `border-slate-200` を基本にする
- 背景は白または `slate-50` を使い、装飾的なグラデーションやぼかしは控える
- 情報のグルーピングは、影よりも余白・罫線・見出しで表現する

## Color

- セクションカードは基本モノクロームで統一する
- 色は画像、状態表現、必要なアクセントに限定する
- プロジェクト画像は情報として扱うため、白黒化しない

## Project List

- 一覧の分類は「案件領域」で揃える
- 自分の役割、担当範囲、視点はカード本文や詳細ページで説明する
- バッジや見出しに役割名と領域名を混ぜない
- カードでは案件領域をバッジ、役割を小さなタグとして分けて表示する
